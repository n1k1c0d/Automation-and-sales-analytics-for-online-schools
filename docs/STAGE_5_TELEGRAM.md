# Доставка ежедневного отчёта в Telegram

Workflow **EduFlow — Daily Sales Report** формирует отчёт через FastAPI и передаёт одному получателю четыре агрегированных KPI. В редакторе уже есть ручной триггер и расписание на 09:00 по Москве. Экспорт можно публиковать с отключённой отправкой до регистрации бота. [Запуск отчётов и подготовка базы](STAGE_5_N8N.md)

## Создать бота и подключить Credentials

1. В Telegram откройте официальный **@BotFather**, отправьте `/newbot`, задайте название, например **EduFlow Sales Reports**, и свободное имя с окончанием `bot`. Скопируйте выданный токен. [BotFather](https://t.me/BotFather)
2. Получатель должен открыть созданного бота в **личном** чате и нажать **Start**.
3. В PowerShell из корня проекта поднимите обработчик доставки.

```powershell
$compose = @('-f', 'docker-compose.yml', '-f', 'compose.n8n.yaml')
docker compose @compose up -d --build --wait telegram-delivery
```

4. Откройте **Credentials → Create credential → Telegram API** в локальном n8n. Задайте имя **EduFlow Telegram**, вставьте токен в **Access Token**, укажите **Base URL** `http://127.0.0.1:5687` и сохраните. Проверка подключения вызывает `getMe`. Токен хранится зашифрованным в томе n8n вместе с локальной конфигурацией экземпляра. Ключ шифрования и том требуют защищённой резервной копии. [Локальный n8n](http://localhost:5678), [Telegram credentials](https://docs.n8n.io/integrations/builtin/credentials/telegram/)

## Разрешить личный чат

В корне проекта запустите помощник:

```powershell
uv run --locked python -m scripts.telegram_chat_id
```

Введите токен из @BotFather в скрытое поле. Помощник проверит токен и покажет имя бота. Откройте личный чат с этим ботом, нажмите **Start** и отправьте показанную проверочную строку одним сообщением. Вернитесь в терминал и нажмите **Enter**. Скопируйте выведенную строку `EDUFLOW_TELEGRAM_CHAT_ID=…` в локальный `.env`. Токен используется в памяти процесса. При ошибке Telegram помощник показывает HTTP-статус.

Это действие оператора при настройке нового бота. Workflow не читает входящие сообщения. В локальном `.env` задайте `EDUFLOW_TELEGRAM_CHAT_ID` равным проверенному положительному числу и выполните `docker compose @compose up -d --wait telegram-delivery`. Проверьте готовность командой `docker compose @compose ps`. В Git хранится пустой пример настройки. [Telegram getUpdates](https://core.telegram.org/bots/api#getupdates)

## Отправить первый отчёт и включить расписание

1. Откройте **EduFlow — Daily Sales Report**. При первой установке импортируйте экспорт по инструкции n8n. Если версия уже содержит **Prepare Telegram delivery**, продолжайте в редакторе. Повторный импорт экспортного файла сбрасывает локальную привязку credential и настройки отправки. [Импорт и публикация](STAGE_5_N8N.md#ручная-проверка-и-публикация)
2. Включите узел **Telegram Send Message** и выберите **EduFlow Telegram**. Оставьте выражение **Chat ID** из экспорта. Оно передаёт локальному обработчику идентификаторы отчёта и выполнения. Обработчик сам подставляет проверенный ID из конфигурации.
3. В **Prepare Telegram delivery** установите `sendManual = true`. Запустите **Execute Workflow → Manual demo**. На демонстрационной базе сообщение содержит период 01.06–31.08.2026, срез 31.10.2026, сумму **8 506 500,00 ₽**, **105** оплативших лидов, средний чек **81 014,29 ₽** и конверсию **39,33 %**.
4. Сверьте сообщение в разрешённом чате с **Executions → Delivery receipt**. Успешная отправка имеет статус `sent`, положительный `message_id` и запись о попытке. Повторите ручной запуск. Для того же отчёта ожидается `already_sent`, тот же `message_id` и ноль новых попыток.
5. Для ежедневной доставки установите `sendScheduled = true` и нажмите **Publish**. Параметр `sendManual` можно вернуть в `false`. В 09:00 по `Europe/Moscow` действующий **Daily 09:00** формирует отчёт за предыдущий завершённый день. Проверьте выполнение с триггером расписания и сообщение в чате. Для отключения ежедневной отправки опубликуйте версию с `sendScheduled = false`.

## Что увидит получатель

В текст входят название системы, тип отчёта, даты, срез, сумма успешных оплат, число оплативших лидов, средний чек, конверсия из урока в оплату и строка о формировании отчёта. При отсутствии продаж сумма равна **0,00 ₽**, число лидов равно **0**. Для неопределённого среднего чека или конверсии выводится **«нет данных»**. Отсутствие обязательного поля в ответе API завершает запуск до отправки. Обработчик отправляет обычный текст длиной до 4096 символов. В Telegram передаются только `chat_id` и `text`. [Telegram sendMessage](https://core.telegram.org/bots/api#sendmessage)

## Журнал, повторы и защита от дублей

Штатный узел Telegram обращается к обработчику через loopback в сетевом пространстве n8n. Обработчик делает HTTPS-запрос по фиксированному адресу `api.telegram.org`, проверяет ответ и передаёт в n8n только квитанцию. Приём через webhook не нужен. Порт обработчика не публикуется на хосте. Полный ответ Telegram может содержать имя пользователя, поэтому история выполнений получает только время, период, ID выполнения, статус, число и результаты попыток, код ошибки и подтверждённый ID сообщения.

| Результат в Delivery receipt | Что произошло и как действовать |
|---|---|
| `skipped` | Для этого типа запуска отправка отключена. |
| `sent`, `already_sent` | Telegram подтвердил сообщение в указанном личном чате. Во втором случае квитанция получена из журнала предыдущей отправки. |
| `recipient_not_configured` | Исправьте положительный числовой ID в локальном окружении и пересоздайте сервис доставки. |
| `authentication`, `bad_request_or_chat`, `bot_blocked` | Проверьте токен, ID и доступность бота для получателя. Автоматический повтор этой ошибки отключён. |
| `rate_limit` | При 429 учитывается `parameters.retry_after`. При ожидании свыше 15 секунд текущий запуск заканчивается ошибкой. Повторите позже, после указанной Telegram паузы. |
| `telegram_unavailable`, `network_unavailable` | При явном отказе Bot API с 5xx или сетевой ошибке до передачи допускаются до трёх попыток. Базовые паузы — одна и две секунды. |
| `unknown` | При таймауте после передачи, потере подтверждения или незавершённой записи сначала проверьте чат и журнал. Такой запуск завершается ошибкой. Для зарезервированного отчёта автоматическая повторная отправка блокируется. |

Перед сетевым вызовом обработчик резервирует комбинацию получателя, дат, среза и фильтров в томе `telegram_delivery_data`. Это защищает от параллельных запусков и повторов после перезапуска. При подтверждённом отказе следующему отдельному запуску разрешена новая попытка. Смена периода или фильтров образует другой отчёт. Telegram не предоставляет ключ идемпотентности для `sendMessage`. При потере локального тома защита от дублей теряется. Статус `unknown` может потребовать проверки даже тогда, когда сообщение фактически пришло. [Ответы Bot API и retry_after](https://core.telegram.org/bots/api#responseparameters)

## Проверки без реального бота

Команды запускаются на демонстрационной базе из корня проекта. Для модульных проверок нужен Node с поддержкой `node:sqlite`. В интеграционном тесте используется образ n8n проекта, временная зашифрованная credential и локальная имитация Telegram. Тесты не читают рабочую credential и не отправляют сообщения в Telegram.

```powershell
node --test tests/n8n/telegram_delivery.test.mjs
docker compose @compose run --rm --no-deps -T -v ./tests/n8n:/opt/eduflow/tests:ro -v ./workflows/telegram:/opt/eduflow/telegram:ro --entrypoint node n8n /opt/eduflow/tests/check_telegram.mjs
```

Фактические результаты и состояние проверки с настоящим ботом приведены в [отчёте пятого этапа](STAGE_5_TEST_REPORT.md).
