## Воспроизведение автотестов

```powershell
uv sync --locked
uv run --locked python -m scripts.check_db
uv run --locked alembic current
uv run --locked alembic check
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked python -m pytest --integration -q -ra -W error
```

Автотесты используют локальные имитации ответов OpenAI и временные базы PostgreSQL. Проверка классификации на этих тестах охватывает подсчёт качества и обработку ответов. Фактическую точность выбранной модели измеряет отдельная команда.

## Реальная оценка и лимиты

Статус на 19 ноября 2026 года — ожидается `OPENAI_API_KEY` в локальной конфигурации. Пробный вызов `evaluate` завершился с кодом 2 на проверке настроек до обращения к OpenAI. Реальная точность, частота обрывов, фактическая модель и расход токенов будут зафиксированы после запуска с настроенным ключом.

Стандартная проверка использует 18 примеров в трёх тарифицируемых запросах. Для оценки влияния размера партии повторите дополнительный набор с размерами 8 и 4 при неизменных модели и лимите. Дополнительный набор требует соответственно 3 и 6 запросов. [Настройка ключа и лимитов](LLM.md#настройка)

```powershell
$results = 'data/local/stage-4'
New-Item -ItemType Directory -Force $results | Out-Null
uv run --locked python -m scripts.ai_sales evaluate |
  Set-Content -Encoding utf8 "$results/classification-smoke.json"

foreach ($batchSize in 8, 4) {
  uv run --locked python -m scripts.ai_sales evaluate data/synthetic/ai/rejection_challenge_cases.json --batch-size $batchSize |
    Set-Content -Encoding utf8 "$results/classification-batch-$batchSize.json"
}
```

Из JSON перенесите в отчёт точность, ошибки и пропуски по каждой категории, фактические модели из `batches`, лимиты из `settings` и токены из `usage_by_request`. Для оценки обрывов сравните `output_limit_batches` и `output_limit_rate_pct` при одинаковой модели. Размер партии и лимит подбираются по этим замерам.

Для проверки сводок сохраните обычный SQL-отчёт и выполните `summarize` с теми же периодами. Зафиксируйте используемый лимит, модель, статус и токены. При обрыве сравните повторный прогон с отдельным лимитом сводки. [Создание SQL-отчёта и запуск сводки](AI_ANALYSIS.md#сводки-и-вопросы-по-kpi)
