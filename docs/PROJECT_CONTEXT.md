# Контекст EduFlow AI

Спецификация 1.0. Планируемое имя репозитория — `eduflow-ai`.

## Продукт

EduFlow AI объединяет данные о работе отдела продаж онлайн-школы. Сейчас такие данные часто распределены между CRM, Excel, Google Sheets и внутренними сервисами. Платформа должна сократить ручную подготовку отчётов, помочь сравнивать эффективность менеджеров и каналов и показать, на каких шагах падает конверсия. Пользователи — руководители отделов продаж и образовательных проектов, коммерческие директора, бизнес-аналитики, аналитики данных и CRM-специалисты.

Проект предназначен для портфолио начинающего Python-разработчика с опытом в EdTech. Каждая подзадача даёт проверяемый результат. Архитектурные решения, команды проверки и связь с бизнес-задачей должны быть понятны разработчику, который воспроизводит проект или объясняет его на собеседовании.

## Границы первой версии

| Блок | Планируемый результат |
|---|---|
| Данные | Импорт CSV и Excel и загрузка через API. Python проверяет структуру, обнаруживает дубликаты, сообщает об ошибках и записывает данные в PostgreSQL. |
| Аналитика | Лиды, назначенные и проведённые уроки, банковские заявки, оплаты, конверсии, сумма успешных оплат и средний оплаченный чек. Срезы по менеджерам, источникам и датам, динамика и сравнение периодов. |
| Интерфейс | Streamlit с KPI-карточками, воронкой, графиками и таблицами. Фильтры по датам, менеджерам и источникам трафика. |
| REST API | Типизированные запросы и ответы, проверка параметров, ошибки и документация для интеграций. |
| AI | Классификация причин отказов, анализ обезличенных комментариев, сводки, ответы по агрегированным показателям и рекомендации по проверке гипотез. |
| Автоматизация | Запуск обработки и формирования отчётов по расписанию через n8n, отправка результатов в Telegram и обработка сбоев. |

## Архитектура и технологии

- Backend строится как модульный монолит на Python 3.12 и FastAPI. Pydantic проверяет входные данные, pydantic-settings читает настройки из окружения.
- PostgreSQL 16 хранит пять основных сущностей. Доступ к данным реализуется через SQLAlchemy 2.x и psycopg 3. Изменения схемы идут через Alembic.
- SQL и Python рассчитывают показатели. pandas добавляется, когда нужен для импорта или обработки данных. Streamlit использует общий расчёт через API.
- LLM API подключается на этапе 4. Ответы проверяются по структурированной схеме. Числа для сводок берутся из рассчитанных показателей.
- pytest и Ruff используются с появлением прикладного кода. Git хранит историю разработки, GitHub предназначен для портфолио. Docker Compose запускает локальную инфраструктуру.

## Ограничения проекта

- Для первой версии используются синтетические данные без реальных имён, телефонов и других персональных данных клиентов. Секреты хранятся локально в окружении. Чувствительные данные передаются сторонним AI-провайдерам только по отдельному разрешению.
- Денежные суммы хранятся с фиксированной точностью. События имеют время с часовым поясом. Хранение ведётся в UTC, отчётные дни определяются по `Europe/Moscow`.
- Один лид закреплён за одним менеджером. История назначений и финансовая модель возвратов относятся к расширениям.
- KPI проверяются на малых наборах с известными ответами. Операционные и когортные отчёты используют согласованные календарные границы и единицы учёта.
- Схему ведём миграциями Alembic. Микросервисы, Kafka, Kubernetes и очередь задач находятся за пределами первой версии.
- Зависимости добавляются по мере реализации. Redis рассматривается при потребности в кэшировании, pgvector при появлении RAG, LangChain или LangGraph при конкретной задаче оркестрации. DataLens, Power BI и другие расширения перечислены в дорожной карте.
