## Этап 1. Инициализация и фундамент

- **TASK-1.1** — рабочий каталог, Git, структуры модулей, проектная документация, шаблон окружения и первый коммит.
- **TASK-1.2** — Python 3.12, виртуальное окружение, `pyproject.toml`, стартовые зависимости, FastAPI с `/health`, первый тест и Ruff.
- **TASK-1.3** — PostgreSQL 16 в Docker Compose, постоянный том, проверка готовности, настройки из окружения и проверка подключения Python после перезапуска.
- **TASK-1.4** — точная модель пяти таблиц, ER-диаграмма, статусы, обязательность, ключи, ограничения и индексы с учётом KPI.
- **TASK-1.5** — SQLAlchemy-модели, metadata, Alembic и первая проверенная миграция с применением и откатом.
- **TASK-1.6** — сервис записи и чтения менеджера, обработка ошибок, модульные и интеграционные тесты с отдельной БД, воспроизведение установки и итоговый коммит.
- **TASK-1.7** — независимый прогон с PostgreSQL, проверки ограничений для событий, сверка миграций и решение по повторному импорту. Контрольный шаг перед генерацией данных.

## Этап 2. Данные и SQL-аналитика

- **TASK-2.1** — генератор синтетических данных для примерно 500 лидов и связанных менеджеров, уроков, банковских заявок и оплат.
- **TASK-2.2** — импорт CSV и Excel в PostgreSQL, проверка структуры и значений, дедупликация по внешней паре и понятные результаты по ошибочным строкам.
- **TASK-2.3** — SQL-запросы и общий слой расчёта KPI для событийных и когортных отчётов. Проверки на небольшом наборе с известными результатами.
- **TASK-2.4** — финальный аудит с PostgreSQL, эталонный тест 12 KPI на 500 лидах, строгая проверка состава CSV-каталога, профиль конверсий и отчёт этапа 2.

## Этап 3. FastAPI и BI

- **TASK-3.1** — REST API для приёма данных и выдачи KPI. Схемы, проверка фильтров, документация и тесты HTTP-сценариев.
- **TASK-3.2** — дашборд Streamlit поверх API. Карточки, воронка, динамика, сравнение периодов и таблицы с фильтрами по датам, менеджерам и источникам.
- **TASK-3.3** — финальная проверка API и BI. Правило даты среза, справочники фильтров по всей базе и [отчёт о тестировании](STAGE_3_TEST_REPORT.md).

## Этап 4. LLM и AI-аналитика

- **TASK-4.1** — интеграция LLM API, ключ из окружения, структурированные ответы, проверка схемы, обработка таймаутов, лимитов и сбоев. Учёт расходов API.
- **TASK-4.2** — классификация и анализ обезличенных причин отказов, сводки, ответы по агрегатам и рекомендации по проверке гипотез. Проверка на тестовых примерах.
- **TASK-4.3** — исправления статуса сводки, защита комментариев, замер точности и лимитов. [Отчёт этапа 4](STAGE_4_TEST_REPORT.md)
- **TASK-4.4** — переход на GroqCloud, резервный режим классификации, оценка Qwen и финальная регрессия перед публикацией в `master`. [Статус PR и подзадач](TASKS.md)

## Этап 5. Автоматизация через n8n

- **TASK-5.1** — развёртывание n8n и сценарий регулярного запуска обработки и формирования отчёта через API.
- **TASK-5.2** — ручная и автоматическая доставка отчёта в Telegram подтверждены. Рабочее расписание — ежедневно в 09:00 (`Europe/Moscow`). Повтор отчёта возвращает `already_sent`. [Приёмка доставки](STAGE_5_TEST_REPORT.md#подтверждение-доставки-по-расписанию)

## После MVP

До публичного развёртывания API обязательны авторизация импорта, отдельные права чтения и записи, проверка доступа к административным маршрутам и тесты отказов. [Требования к публичному запуску](API.md#перед-публичным-развёртыванием)

Возможные расширения включают RAG и поиск по документам с pgvector, LangGraph-агентов, MCP-интеграции, Redis, планировщик ETL, DataLens или Power BI, расширенную статистику, предиктивную аналитику и CI/CD.

Статусы, зависимости отдельных задач и критерии приёмки приведены в [TASKS.md](TASKS.md).
