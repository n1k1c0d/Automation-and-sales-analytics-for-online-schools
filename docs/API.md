# REST API EduFlow AI

Запустите PostgreSQL, примените миграции и запустите Uvicorn по [инструкции проекта](../README.md#локальный-запуск). В примерах используется `http://127.0.0.1:8000`. Интерактивная документация доступна по адресу `/docs`, схема OpenAPI по адресу `/openapi.json`. Маршрут `GET /health` проверяет доступность процесса FastAPI. Текущий запуск рассчитан на локальную работу с синтетическими данными.

## GET /api/v1/metrics

Возвращает 12 KPI продаж, разбивки и динамику за выбранный период. Даты в формате `YYYY-MM-DD`, обе границы периода включены по московскому времени.

| Параметр | Правило |
|---|---|
| `start_date`, `end_date` | Обязательные границы периода. Начало должно быть не позже конца. Максимум 366 календарных дней. |
| `cutoff_date` | Дата среза когортных исходов. Допустима дата `end_date` или позже. По умолчанию равна `end_date`. |
| `manager_id` | UUID менеджера из `by_manager`. |
| `source` | Точное значение канала лида, например `webinar`. Пробелы по краям удаляются. Фильтры канала и менеджера применяются совместно. |
| `compare_start_date`, `compare_end_date` | Необязательные границы второго периода. Указываются вместе. |
| `compare_cutoff_date` | Срез второго периода. Допустима дата `compare_end_date` или позже. По умолчанию равен `compare_end_date`. |

```powershell
Invoke-RestMethod -Uri 'http://127.0.0.1:8000/api/v1/metrics?start_date=2026-06-01&end_date=2026-08-31&cutoff_date=2026-10-31'
```

Ответ HTTP 200 содержит `period`, применённые фильтры `manager_id` и `source`, итог `total`, дневные показатели `daily`, срезы `by_manager` и `by_source`. При сравнении ответ содержит два таких отчёта в полях `current` и `comparison`. Фильтры общие для обоих периодов. Даты и срезы задаются отдельно, расчёт выполняется в одном снимке PostgreSQL.

Срез до конца соответствующего периода возвращает HTTP 422. Суммы и рассчитанные проценты передаются десятичными строками. При пустой выборке счётчики равны нулю, дни остаются в `daily`, а средний чек и конверсии с нулевым знаменателем равны `null`. [Формулы KPI](KPI_DEFINITIONS.md), [эталон для 500 лидов](STAGE_2_TEST_REPORT.md#эталонные-kpi)

## GET /api/v1/dimensions

Возвращает справочники для фильтров без параметров периода. В массиве `managers` перечислены все менеджеры, включая тех, у кого ещё нет лидов. У каждой записи есть `manager_id` и `manager_name`. Массив `sources` содержит уникальные значения `leads.source` за всю историю. Для пустой базы оба массива пусты.

```powershell
Invoke-RestMethod -Uri 'http://127.0.0.1:8000/api/v1/dimensions'
```

Выбор менеджера или канала без событий в текущем периоде возвращает пустой отчёт с HTTP 200.

## POST /api/v1/import

Принимает `multipart/form-data`. В поле `source_system` передайте постоянный код источника из 1–64 строчных латинских букв, цифр и подчёркиваний. В повторяемых полях `files` передайте одну книгу `.xlsx` или до пяти CSV с разными именами из списка `managers.csv`, `leads.csv`, `lessons.csv`, `bank_applications.csv`, `payments.csv`. В книге Excel листы названы по таблицам. Для ячеек Excel со значениями даты и времени передайте `excel_timezone`, например `Europe/Moscow`.

Общий размер HTTP-запроса ограничен 5 МиБ. Для книги Excel размер распакованного содержимого ограничен 50 МиБ. [Структура таблиц и правила импорта](../README.md#импорт-csv-и-excel)

Пример загрузки стандартного набора, сгенерированного в папку по умолчанию. В Linux и macOS команда называется `curl`.

```powershell
curl.exe -F 'source_system=synthetic_42' `
  -F 'files=@data/synthetic/generated/managers.csv' `
  -F 'files=@data/synthetic/generated/leads.csv' `
  -F 'files=@data/synthetic/generated/lessons.csv' `
  -F 'files=@data/synthetic/generated/bank_applications.csv' `
  -F 'files=@data/synthetic/generated/payments.csv' `
  'http://127.0.0.1:8000/api/v1/import'
```

Пример загрузки Excel.

```powershell
curl.exe -F 'source_system=demo_crm' -F 'excel_timezone=Europe/Moscow' `
  -F 'files=@data/local/sales.xlsx' 'http://127.0.0.1:8000/api/v1/import'
```

Ответ HTTP 200 содержит `source_system`, счётчики `tables` и список `issues`. По каждой таблице возвращаются `inserted`, `duplicate`, `conflict` и `invalid`. Частично успешная загрузка также возвращает HTTP 200. Корректные строки сохраняются, а `issues` содержит таблицу, номер строки, результат и причину для каждой отклонённой строки. Повтор совпавшей строки даёт `duplicate`. Если данные отличаются, импорт возвращает `conflict` и сохраняет существующие значения.

## Ошибки HTTP

| Код | Условие |
|---|---|
| `400` | Ошибка разбора формы. |
| `413` | Превышен лимит размера запроса или книги. |
| `422` | Неверные параметры запроса, неподдерживаемый набор файлов или ошибка структуры импорта. При ошибке структуры строки из запроса в базу не пишутся. |
| `503` | Не удалось выполнить операцию PostgreSQL. Проверьте параметры подключения и миграции. |

Для ошибки `422` поле `detail` содержит описание или список ошибок валидации с расположением каждого поля. При `503` ответ содержит общее описание без деталей подключения.

## Перед публичным развёртыванием

Текущий локальный запуск рассчитан на синтетические данные и принимает импорт без авторизации. Для публичного запуска обязательны следующие шаги.

- Включить авторизацию для импорта, например API-ключ, и настроить отдельные права на чтение отчётов и изменение данных.
- Определить доступ к Swagger, OpenAPI и будущим административным маршрутам. Ограничить доступ к тем из них, которые предназначены для администраторов.
- Проверить, что импорт без ключа или с недействительным ключом отклоняется, а право чтения отчётов не даёт права импортировать данные.
