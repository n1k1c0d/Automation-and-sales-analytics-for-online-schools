# AI-аналитика продаж

Команды принимают синтетические или предварительно обезличенные данные. Для запроса к модели нужен ключ в `OPENAI_API_KEY`. [Настройка клиента](LLM.md)

## Причины отказов

Передайте JSON-массив строк. За один запуск `classify` можно обработать до восьми комментариев длиной до 800 символов каждый.

```json
["Для нас слишком дорого.", "Банк не одобрил рассрочку.", "Причину не сообщили."]
```

```powershell
uv run --locked python -m scripts.ai_sales classify data/local/comments.json
```

В результате `comment_id` соответствует позиции комментария в файле, начиная с 1. Для определённой причины клиент проверяет, что `evidence` является короткой дословной цитатой из этого комментария. Счётчики `counts` вычисляются по проверенным результатам.

| Код | Причина |
|---|---|
| `price` | Стоимость самого курса. |
| `bank_declined` | Банк отклонил заявку. |
| `financing_terms` | Условия или недоступность рассрочки. |
| `schedule` | Конфликт времени занятий. |
| `program_fit` | Программа, уровень, преподаватель или формат. |
| `competitor` | Выбрана другая школа, курс или репетитор. |
| `postponed` | Решение отложено без более конкретной причины. |
| `other` | Известная причина вне списка. |
| `unclear` | Причина неизвестна, предположительна или неоднозначна. Цитата равна `null`. |

## Сводки и вопросы по KPI

Сохраните JSON обычного отчёта по продажам. Для сравнения можно передать вывод этой же команды с `--compare` и датами второго периода.

```powershell
New-Item -ItemType Directory -Force data/local | Out-Null
uv run --locked python -m scripts.sales_report --start-date 2026-06-01 --end-date 2026-08-31 --cutoff-date 2026-10-31 |
  Set-Content -Encoding utf8 data/local/sales_report.json
uv run --locked python -m scripts.ai_sales summarize data/local/sales_report.json
uv run --locked python -m scripts.ai_sales ask data/local/sales_report.json 'Какой канал принёс больше всего оплат по сумме?'
```

Модель выбирает ссылки на показатели и срезы отчёта. Python берёт значения из исходного JSON, вычисляет разницу между периодами и определяет максимум или минимум для сравнений каналов и менеджеров. При равенстве выводятся все срезы с этим значением. Разницы конверсий выражаются в процентных пунктах. Если значения нет, в JSON остаётся `null`. Вопрос без достаточных данных получает статус `insufficient_data`.

В запрос к модели входят итоговые агрегаты, срезы по каналам и менеджерам, даты и фильтры. Для больших отчётов можно сократить объём исходным фильтром. Поддерживаемые операции включают чтение значений, сопоставление периодов и поиск максимума или минимума по срезам. [Формулы KPI](KPI_DEFINITIONS.md)

Сводка включает до двух предложений о том, что проверить дальше. Возможные проверки касаются состава каналов, посещения уроков, заявок в банк и оплат. У каждой проверки есть ссылка на соответствующий KPI.

## Оценка классификации

В [размеченном наборе](../data/synthetic/ai/rejection_cases.json) 18 синтетических примеров по девяти категориям. Команда ниже отправляет только комментарии, затем сравнивает ответы с эталонными метками и выводит точность, ошибки и статистику токенов по каждой партии. Стандартный набор разбивается на три тарифицируемых запроса.

```powershell
uv run --locked python -m scripts.ai_sales evaluate
```

Тесты проекта используют имитацию ответов OpenAI. Они проверяют цитаты, подсчёты, ошибки на размеченных примерах и совпадение KPI с SQL-отчётом. Команда `evaluate` измеряет качество выбранной модели через OpenAI API.
