# AI-аналитика продаж

Команды принимают синтетические или предварительно обезличенные данные. Классификация, сводки и ответы по KPI используют единый клиент Groq Chat Completions. Ключ задаётся в `GROQ_API_KEY`. [Настройка клиента](LLM.md)

## Причины отказов

Передайте JSON-массив строк. За один запуск `classify` можно обработать до восьми комментариев длиной до 800 символов каждый.

```json
["Для нас слишком дорого.", "Банк не одобрил рассрочку.", "Причину не сообщили."]
```

```powershell
uv run --locked python -m scripts.ai_sales classify data/local/comments.json
```

В результате `comment_id` соответствует позиции комментария в файле, начиная с 1. Для определённой причины клиент проверяет, что `evidence` является короткой дословной цитатой из этого комментария. Счётчики `counts` вычисляются по проверенным результатам.

### Подготовка комментариев

Используйте синтетические примеры или заранее согласованно обезличенные комментарии. При подготовке удалите контакты, имена, адреса, идентификаторы и другие детали, по которым можно узнать человека. Проверьте подготовленный текст перед запуском.

Перед отправкой `classify` и `evaluate` локально проверяют весь вход на распространённые форматы телефонов, email и признаки имён. При срабатывании обработка блокируется целиком. Ошибка выводит номера комментариев и категории совпадений. Проверка эвристическая, поэтому ручная проверка обезличивания входит в подготовку данных. [Ограничения автоматического поиска персональных данных](https://github.com/data-privacy-stack/presidio#main-features)

| Код | Причина |
|---|---|
| `price` | Стоимость самого курса. |
| `bank_declined` | Банк отклонил заявку. |
| `financing_terms` | Условия или недоступность рассрочки. |
| `schedule` | Конфликт времени занятий. |
| `program_fit` | Программа, уровень, преподаватель или формат. |
| `competitor` | Выбрана другая школа, курс или репетитор. |
| `postponed` | Решение отложено без более конкретной причины. |
| `other` | Известная причина вне списка. |
| `unclear` | Причина неизвестна, предположительна или неоднозначна. Цитата равна `null`. |

## Сводки и вопросы по KPI

Сохраните JSON обычного отчёта по продажам. Для сравнения можно передать вывод этой же команды с `--compare` и датами второго периода.

```powershell
New-Item -ItemType Directory -Force data/local | Out-Null
uv run --locked python -m scripts.sales_report --start-date 2026-06-01 --end-date 2026-08-31 --cutoff-date 2026-10-31 |
  Set-Content -Encoding utf8 data/local/sales_report.json
uv run --locked python -m scripts.ai_sales summarize data/local/sales_report.json
uv run --locked python -m scripts.ai_sales ask data/local/sales_report.json 'Какой канал принёс больше всего оплат по сумме?'
```

Модель выбирает ссылки на показатели и срезы отчёта. Python берёт значения из исходного JSON, вычисляет разницу между периодами и определяет максимум или минимум для сравнений каналов и менеджеров. При равенстве выводятся все срезы с этим значением. Разницы конверсий выражаются в процентных пунктах. При частичной доступности значений сводка содержит измеренные KPI и `null` на месте пропусков. Если значений нет ни в одном из периодов, сводка или ответ получает статус `insufficient_data`.

Для сводки Groq получает агрегаты текущего и сравнительного периодов. Для вопроса модель получает текст, даты и справочник доступных KPI и срезов. Например, для вопроса «Какой источник принёс больше всего денег?» она выбирает максимум `paid_amount_rub` по источникам. Денежные суммы для сравнения Python читает локально. Допустимые коды 12 KPI перечислены в строгой схеме ответа. [Формулы KPI](KPI_DEFINITIONS.md)

Используйте синтетические отчёты или заранее проверенные и обезличенные отчёты и вопросы. Перед обращением к Groq приложение проверяет текст вопроса, метки срезов и фильтр источника на признаки персональных данных. Во внешний запрос для менеджера передаётся ключ среза (например, `manager:1`). Полное совпадение подготовленной метки менеджера в вопросе заменяется таким ключом. Метка для отображения и UUID фильтра остаются в локальном результате. Эвристическая проверка может пропускать персональные данные. Перед подключением CRM потребуется отдельная подготовка данных с устойчивыми псевдонимами сотрудников и контролем доступа.

Сводка включает до двух предложений о том, что проверить дальше. Возможные проверки касаются состава каналов, посещения уроков, заявок в банк и оплат. У каждой проверки есть ссылка на соответствующий KPI.

## Оценка классификации

В [основном наборе](../data/synthetic/ai/rejection_cases.json) 18 синтетических примеров по девяти категориям. [Дополнительный набор](../data/synthetic/ai/rejection_challenge_cases.json) содержит 24 примера с неоднозначными причинами и пересечениями банка, стоимости и отложенного решения. Команда `evaluate` отправляет комментарии, затем локально сравнивает ответы с эталонными метками. Стандартный прогон обрабатывает три партии и делает три HTTP-запроса, если каждая партия завершилась с первой попытки.

```powershell
uv run --locked python -m scripts.ai_sales evaluate
```

Отчёт оценки включает точность, ошибки по категориям, модель, настройки и токены по каждому запросу. Партия с `output_limit` учитывается в частоте сбоев, её комментарии помечаются как неклассифицированные. Общая точность считается по всем примерам. При таких сбоях команда сохраняет JSON и возвращает код 1. Для сравнения размеров партий используйте `--batch-size` от 1 до 8. [Методика повторного прогона](STAGE_4_TEST_REPORT.md#реальная-оценка-и-лимиты)

В каждой партии `batches[].attempts` показывает число HTTP-попыток. Массив `usage_by_request` содержит по одной записи на каждую попытку в порядке отправки, включая временные ошибки. Значение `null` означает, что расход этой попытки неизвестен. Повтор партии учитывается в статистике токенов, а каждый комментарий участвует в расчёте точности один раз.
