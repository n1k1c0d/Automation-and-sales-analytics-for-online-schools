## Воспроизведённые отказы

Тест запускал настоящий HTTP Request и JavaScript-узлы n8n. Вместо рабочего FastAPI для этих случаев использовался локальный тестовый HTTP-сервер. Число обращений проверялось по истории узла и, когда соединение устанавливалось, по счётчику сервера.

| Ответ | Попытки | Итог |
|---|---:|---|
| Нулевые продажи, средний чек и конверсия `null` | 1 | Успех. Нули и отсутствующие значения сохранены, пустые разбивки опущены. |
| Сначала HTTP 503, затем корректный JSON | 2 | Один успешный итоговый отчёт. |
| HTTP 422 | 1 | Ошибка с HTTP-статусом. |
| Постоянный HTTP 503 | 3 | Ошибка после ограниченных повторов. |
| Соединение отклонено / сервер не ответил вовремя | 3 в каждом случае | Ошибка транспорта. Тестовый таймаут 300 мс, рабочий — 5 с. |
| Повреждённый JSON / отсутствуют KPI / неверный тип / подменён период | 1 в каждом случае | Ошибка валидации. Узел итогового отчёта не запускался. |

Данные n8n находятся в отдельном локальном томе. Проверка не измеряла восстановление пропущенных запусков при выключенном компьютере или производительность под нагрузкой.

## TASK-5.2 · Доставка отчёта в Telegram

21 ноября 2026 года, Windows, Docker Desktop, n8n 2.48.7 и локальный PostgreSQL. Ручная доставка в разрешённый личный чат подтверждена получателем и квитанцией n8n. Для автоматических проверок использованы отдельная SQLite n8n, временная Telegram credential и имитация ответов Bot API. [Инструкция и команды проверки доставки](STAGE_5_TELEGRAM.md)

| Сценарий | Фактический результат |
|---|---|
| Ручной запуск с настоящим ботом | 21.11.2026 в 18:51 МСК выполнение № 8 завершилось с `success`. Узел Delivery receipt зафиксировал `sent`, одну попытку и положительный `message_id`. Получатель подтвердил, что отчёт пришёл в Telegram. |
| Ручной запуск через штатный Telegram Send Message | Имитация приняла один запрос с полями `chat_id` и `text`. Проверены период и срез, 8 506 500,00 ₽, 105 лидов, 81 014,29 ₽ и 39,33 %. Квитанция содержит `sent`, одну попытку и тестовый `message_id`. |
| Автоматический запуск на стенде | Опубликованная копия с ускоренным триггером отправила один отчёт. В истории n8n сохранены режим `trigger`, успешное выполнение, статус `sent` и ID сообщения. Отдельный прогон без доставки сравнил предыдущий московский день с FastAPI. |
| Повтор и перезапуск | Повторное выполнение из нового процесса n8n прочитало ту же зашифрованную credential и вернуло `already_sent` с нулём попыток. Модульный тест подтвердил блокировку параллельной отправки и сохранение результата при повторном открытии файла SQLite. |
| Качество данных | Нулевые продажи отобразились как 0,00 ₽ и 0 лидов, недоступные значения — «нет данных». Удаление обязательных KPI прервало workflow до Telegram. |
| Ошибки Telegram | Проверены 400, 401, 403, 429, подтверждённый 503 и отказ соединения. После 429 с `retry_after=4` до следующего запроса запрошена пауза 4 с. Для постоянного 429 — всего три попытки. При длительном ограничении, ошибке авторизации или блокировке чат повторно не вызывался. |
| Неоднозначная доставка | Таймаут после запроса, неподтверждённый 502, неправильный чат в квитанции и отсутствие `message_id` дали `unknown`. Повтор с тем же ключом не создал новый запрос. |
| Обработчик недоступен | Штатный узел получил отказ соединения на loopback. Workflow завершился ошибкой `delivery_confirmation_missing`. Квитанция содержит `unknown`, число внешних попыток неизвестно. В данных выполнения тестовый токен отсутствовал. |
| Конфиденциальность | Проверено отсутствие тестового токена и имени профиля из имитации в истории успешного выполнения. В экспорте отсутствуют привязанные Credentials и реальный ID чата. Проверка подключения возвращает только готовность бота. |
