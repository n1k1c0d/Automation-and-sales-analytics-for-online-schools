# Клиент LLM

`LLMClient.generate()` отправляет POST на `https://api.groq.com/openai/v1/chat/completions` через совместимый Python SDK `openai`. Инструкция передаётся в сообщении `system`, данные — в `user`. SDK формирует строгую JSON Schema из модели Pydantic, а клиент передаёт лимит операции в `max_completion_tokens`. [Groq Chat Completions](https://console.groq.com/docs/api-reference#chat-create), [структурированные ответы](https://console.groq.com/docs/structured-outputs)

## Настройка

Задайте `GROQ_API_KEY` в локальном `.env` или окружении процесса. Старые переменные `OPENAI_*` не используются для загрузки настроек `LLMSettings`. Для FastAPI, дашборда и SQL-отчёта ключ не требуется. [Управление ключами Groq](https://console.groq.com/keys)

| Настройка | По умолчанию | Назначение |
|---|---|---|
| `GROQ_API_KEY` | требуется для AI | Ключ проекта Groq. |
| `GROQ_MODEL` | `qwen/qwen3.8-27b` | Идентификатор облачной модели. |
| `GROQ_TIMEOUT_SECONDS` | `60` | Таймаут сетевых операций в секундах. |
| `GROQ_MAX_INPUT_CHARS` | `24000` | Общий лимит символов инструкции и текста запроса. |
| `GROQ_MAX_OUTPUT_TOKENS` | `2048` | Базовый лимит токенов ответа. |
| `GROQ_CLASSIFICATION_MAX_OUTPUT_TOKENS` | базовый лимит | Лимит для классификации и оценки комментариев. |
| `GROQ_SUMMARY_MAX_OUTPUT_TOKENS` | базовый лимит | Лимит для сводок. |
| `GROQ_INPUT_USD_PER_MILLION` | пусто | Цена миллиона входных токенов выбранной модели. |
| `GROQ_CACHED_INPUT_USD_PER_MILLION` | пусто | Цена миллиона кэшированных входных токенов. По умолчанию применяется обычная входная цена. |
| `GROQ_OUTPUT_USD_PER_MILLION` | пусто | Цена миллиона выходных токенов выбранной модели. |

В `.env.example` для классификации и сводок явно заданы стартовые значения по 2048. Удалите или оставьте пустой настройку отдельной операции, чтобы она наследовала базовый лимит.

## Классификация отказов

`classify` принимает 1–8 синтетических или заранее обезличенных комментариев. В каждом должно быть от 1 до 800 символов и хотя бы один непробельный символ. `evaluate` читает размеченный набор целиком и по умолчанию отправляет рекомендуемые партии по два комментария (`--batch-size 2`). До первого запроса приложение проверяет вход на признаки персональных данных. [Подготовка комментариев](AI_ANALYSIS.md#подготовка-комментариев)

Каждая запись ответа содержит `comment_id` (позиция с единицы в текущей партии), `reason` и `evidence`. Допустимые категории — `price`, `bank_declined`, `financing_terms`, `schedule`, `program_fit`, `competitor`, `postponed`, `other`, `unclear`. [Значения категорий](AI_ANALYSIS.md#причины-отказов)

## Режимы JSON и повторы

На бесплатном тарифе запросы и токены входят в лимиты GroqCloud. Временное превышение частоты может дать HTTP 429. При исчерпании квоты клиент возвращает `quota`. Резервный режим доступен только после ошибок генерации в классификаторе. [Лимиты GroqCloud](https://console.groq.com/docs/rate-limits)

При временном HTTP 429, 500, 502, 503 или 504 клиент делает до двух повторов. То же правило действует для HTTP 400 с кодом Groq `json_validate_failed`. Все повторы входят в общий предел трёх попыток. Базовые задержки составляют 1 и 2 секунды со случайной добавкой до 0,5 секунды. Клиент учитывает `Retry-After` как минимальную задержку. Если сервер просит ждать более 30 секунд, команда сразу возвращает соответствующую ошибку. Перенаправления и встроенные повторы SDK отключены. [Ограничения Groq](https://console.groq.com/docs/rate-limits), [коды ошибок](https://console.groq.com/docs/errors)

1. Первая попытка использует `json_schema` с `strict: true`.
2. После HTTP 400 `json_validate_failed` клиент повторяет строгий запрос.
3. Если Groq второй раз подряд вернул ту же ошибку при классификации, последняя попытка использует `json_object`. Клиент добавляет схему в системную инструкцию, сохраняя комментарии, модель и лимит токенов. Если инструкция превышает лимит входа, клиент возвращает ошибку второй попытки. При неудаче самой третьей попытки вызывающий код получает `LLMError`. [Режим JSON Object в Groq](https://console.groq.com/docs/structured-outputs#json-object-mode)

## Валидация ответа

В обоих режимах Pydantic проверяет результат по внешней схеме `GroqClassificationResponse` — обязательные поля, типы, допустимая категория и запрет лишних полей. Внутренняя `ClassificationPlan` ограничивает размер партии и ID диапазоном 1–8, а длину строковой цитаты — 1–160 символами. Затем Python проверяет, что каждому входному ID соответствует ровно одна запись, и восстанавливает входной порядок.

После этих проверок для `unclear` устанавливается `evidence=null`. Для определённой причины Python берёт исходный комментарий целиком, если в нём до 160 символов включительно. Для более длинного текста требуется непрерывная дословная цитата из того же комментария с хотя бы одним непробельным символом. Точность выбора категории измеряет `evaluate`, сравнивая ответ с эталонной меткой.

Сообщение `Groq rejected generated JSON` означает, что генерацию отклонил сам Groq. Сообщение `The returned JSON failed local Pydantic validation` означает, что клиент получил ответ и обнаружил нарушение схемы. Оба случая используют код `invalid_response`. Ошибки локальной проверки схемы, идентификаторов или цитат сразу завершают вызов. Это также относится к ошибкам авторизации, исчерпанию квоты, таймауту и отказу модели.

Клиент сначала проверяет `finish_reason`. При достижении лимита возвращается ошибка `output_limit` с доступной статистикой токенов. При успешном завершении текст из `choices[0].message.content` проходит строгую локальную проверку по переданной модели Pydantic.

## Диагностика и расходы

`LLMResult` содержит объект Pydantic, фактическую модель, идентификаторы ответа и запроса. При обращении в поддержку Groq используйте `request_id` последней попытки, если сервер вернул его. Поле `usage` относится к последней попытке. Клиент берёт входные, выходные и суммарные токены из `prompt_tokens`, `completion_tokens` и `total_tokens`. При отсутствии `prompt_tokens_details.cached_tokens` поле `cached_input_tokens` равно `null`. При настроенных ценах клиент оценивает стоимость через `Decimal` и применяет скидку только к явно указанным кэшированным токенам. Значение `estimated_cost_usd=null` означает, что оценка стоимости недоступна.

CLI выводит режим последней HTTP-попытки в `response_mode` и фактическое число попыток в `attempts`. Если были повторы, массив `retry_usage` содержит статистику предыдущих попыток в порядке отправки, а `usage` относится к последней. При отсутствии статистики соответствующая запись равна `null`. Оценка полного расхода возможна, когда счётчики доступны для каждой попытки.

`LLMError.code` различает ошибки ввода, проблемы с ключом, ограничение частоты, исчерпание квоты, таймаут, сбой провайдера, отказ модели, исчерпание лимита выходных токенов, незавершённую генерацию и нарушение схемы. Для отказа модели, незавершённой генерации и ответа с нарушением схемы счётчики токенов доступны в ошибке, если провайдер передал их. В журнал приложения на уровне INFO передаются модель, идентификатор запроса, статус и счётчики.

## Проверка

Автотесты используют локальный тестовый HTTP-транспорт. Они проверяют формат исходящего запроса, валидацию JSON, обработку сбоев и расчёт стоимости.

```powershell
uv run --locked python -m pytest tests/unit/test_llm_client.py -q
```

Проверить чтение локального ключа и вывести модель без обращения к API можно из корня проекта.

```powershell
uv run --locked python -c "from app.core.config import LLMSettings; print(LLMSettings().model)"
```

Для проверки соединения выполните `uv run --locked python -m scripts.check_llm`. Команда отправит одно синтетическое сообщение и выведет статус, модель и токены.
